# Labor Governance

Labor is currently a maintainer-led open-source project.

## How decisions are made

- Small fixes and scoped improvements are decided through pull-request review.
- Product direction, architecture changes, new cloud permissions, and breaking migrations should begin in GitHub Discussions.
- Security decisions may be handled privately until disclosure is safe.
- Maintainers may reject changes that weaken user ownership, security, portability, or the Forever Free Pledge.

## Project commitments

The official Labor project will:

- Keep official capabilities in the public repository.
- Avoid subscriptions, premium tiers, and paid feature gates.
- Keep generated products in the cloud selected by the user.
- Explain consequential permission and architecture changes in public.
- Welcome respectful disagreement and evidence from real use.

Changes that could weaken the [Forever Free Pledge](docs/FOREVER_FREE.md) require a public proposal and an explicit governance update. They should never arrive as an incidental code change.

## Becoming a maintainer

Maintainer access is earned through sustained, constructive contributions, sound judgment around cloud/security boundaries, respectful collaboration, and care for the project's mission. Existing maintainers decide access in public when practical.
